# Founder Comment

One rule sits at the center of this, bolted on permanently after a real
correction: agree first, and never let a comment claim an experience the
user doesn't actually have.

**This never auto-comments.** No browser tool posts a comment on the
user's behalf, under any framing. It hands back labelled options. The user
posts one.

## Finding real posts

Don't invent example posts. Read actual ones, from the feed or from named
people the user wants visibility with. To get a real, working link: a
post's own activity page (not the general home feed, which often won't
expose one) usually surfaces it. If a link genuinely can't be found after
a real attempt, say so plainly rather than fabricating one, and hand over
the poster's name and the post's first line instead so the user can find
it themselves in a few seconds.

## Drafting the comment

1. **Agree with or build on what the poster actually said.** Don't open
   with a disagree or a hot take here, the goal is goodwill, not a debate.
   Save contrarian takes for the user's own posts.
2. **Never fabricate experience.** No "our best-performing post", no
   implied firsthand result the user doesn't actually have. If a claim
   would sound lived-in but isn't true, cut it entirely.
3. **Do a real, quick search on whatever the post is about**, and bring
   back one genuine, sourced fact or stat that extends the poster's point.
   Name or link the source. This replaces the fabricated-experience move
   with something actually true.
4. Two to four sentences, one idea, no emoji opener, never "Great post!",
   specific enough that it couldn't be pasted under a different post on
   the same general topic.

Give two or three labelled options per post, each a different angle (add
a researched datum, extend one line, ask the real question), and
recommend which one to post and why, briefly.

## Stealing formats, not words

When a post's structure is worth learning from, pull out its shape (a
numbered transformation list, a scene-then-lesson arc, a single-claim-
then-proof format) and apply that shape to the user's own real material.
Never reuse its actual sentences.

## Output

For each real post: who wrote it, a one-line summary of what it's about,
the link if one was found (or a plain note that none could be found, plus
the poster's name and first line), the labelled comment options, and a
one-line recommendation of which to post and why. Never claim a comment
has been posted.
